# 数据与金额口径

设计契约，尚非已实现接口。

实体分别存储，主键不可用商品标题代替：

- AccountRef：平台、国家站、匿名账号标识、当前登录核验时点；不存凭证。
- OrderLine：平台/账号/订单号/行ID、原商品货号与规格、数量、原实际分摊价、现金与储值等组成、支付债务、履约/售后状态与来源时间。
- ProductMatch：候选货号和规格、与原品一致/不一致/未知的字段及证据。
- Quote：目标与数量、原币、币种、账号权益、优惠券和互斥组、运税费、结算总额、每商品报价覆盖数量、有效时点和证据来源、付款前待验证条件。
- BundleScenario：整组商品与额外凑单品、整组应付与分摊、共享券使用次数、保留集合、可否获得全部必需品；不能只比较各行最低数。
- Action：对象、原状态、计划动作、依赖、授权范围/版本/费用上限、幂等键、执行状态、回读证据。状态含prepared、submitted、verified、unknown、failed、needs_user；unknown必须先对账。
- ReturnCase：原订单行与实际物品、真实原因、数量、可退金额、受理和寄回期限、平台返回的退回约束。
- Parcel：所含售后/数量、实际完整收件信息的本地引用、平台允许合包证据、预约区间/时区、取件码、承运商与真实运单、揽收证据。
- Refund：每笔金额/币种、来源、现金或储值返还、平台状态、到账核对状态、核对方式与时间。

## 金额

先冻结同一“最终保留物品集合”和原始实际成本B，跨平台同品可比必须成立。

- 当前最终净成本C = 原付款 + 新付款 + 相关费用 - 已到账退款（含已证实退差价）。现金与储值账分别列示，并说明储值可用范围；不能把退回购物金叫现金到账。
- 已实现净节省 = B - C，只有原退款到账、替代交易与必需费用确定且保留集合满足时才认定闭环。
- 流程未完成只列预计净节省；退款额度未知或运费可能反转结果时列区间或无法判断。
- 不再需要的商品直接退款计“回收资金”，与同一保留集合换购节省分开。
- 价保后再退款不能把同一返还算两次；多退少退、券追回、赠品、运费险实际赔付按平台回执入账。
- 海外另列当地税、国际/境内运费、关税、汇率时点、信用卡换汇费、退税可得性、退货费和退款汇差。不把预估汇率金额标为最终成交价。

## 验收场景

干净环境的新用户用自己的账号，不借作者凭证或私有路径完成一次订单读取→同款结算→授权动作→平台状态回读→到账核对。对纯读取也可明确验收，执行能力逐项上线。

反例必须验证：同名不同货号；80/90错配；套装1份与2件；列表未加载完；券不可复用；额外凑单支出抵消优惠；部分退款/券追回；超时但平台已下单；支付未完成；用户控制权硬停；同地址却不同退货标签；退件码误作运单；退错物品；平台退款成功但未到账。

关键交易错误、凭证泄露、越权动作验收为零容忍；同时记录覆盖率、节省口径、人工介入次数与时间，不靠测试数量证明可用。
