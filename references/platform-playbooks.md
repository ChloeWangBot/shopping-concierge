# 平台执行检查表

本文件是操作检查表，不是已实现API或全用户验证过的自动化适配器。使用时先确认当前宿主的实际连接器/受管浏览器权限。执行以页面当前可见状态为准，不复用别人的登录态、地址、订单号或旧CSS选择器。

## 新用户首次使用

先确认宿主能否打开官方页面、保留登录态和交还控制权。让用户在本人浏览器登录**所选**平台；已有登录态只核当前账号/国家站点。没有工具权限时接受用户提供的脱敏清单做离线整理，明确尚未操作平台。不要要求购买额外服务才能开始，实际缺能力则给具体缺口。

建立本批范围：目标物品/规格/数量、当前保留与准备退回、允许商家类型、可买平台、预算、最小值得折腾的净差额、期限与取件偏好。订单和资产读取范围最小化，不默认扫描多年历史。

每个平台逐项记录能力：未验证 / 已验证读取 / 已验证结算 / 已验证具体动作 / 需要本人 / 不支持；带证据时间。一个成功的退货不代表该平台所有商品和步骤都能执行。

## 京东

- 订单列表可能拆父单和子单。使用实际子单及行项目，父单合计不能当每件单价；进订单详情核优惠分摊。先享后付是负债，确认收货/支付认证可能改变资金状态。
- 购物车加购只是候选。核货号、色号、尺码、数量及有货，进入结算页才记录账号可用优惠；不要把推荐区和“最近看过”的价当当前订单价。
- 按优惠路径表检查店铺入会券、现有PLUS权益、平台补贴、跨店凑单及支付优惠。父单整组金额与子单分摊分别记录；不把PLUS开通成本或凑单额外支出隐藏在低单价里。
- 取消订单与售后不同：未发货优先核取消范围，防联动取消其他子单；已发货不能仅为使用退款入口虚假确认收货。拦截要核平台结果，不把已联系当已拦截。
- 高价单已取消时不重复申请；较早的同款订单应单独对应实物和售后，不能以商品名自动跨单操作。
- 价保查看具体标识、有效期、适用品和排除项；跨平台价格不直接证明京东可补差。
- 取件时间用平台可选区间并标日期/时区。“最远时间”等偏好在本批复用，不能照搬别的用户。

## 拼多多

- 搜索价、券后展示、规格弹窗和确认订单价格可能不同。选择精确SKU后核实最终结算，并观察券是否可重复使用；拼单尚未成团不能标成待发货。
- 核百亿补贴/店铺会员/新客及支付渠道的实际资格；不能用其他型号的低搜索价或其他商品返佣替代目标SKU核价。返利与补贴是否兼容须查当前渠道规则和跟单证据。
- 页面跳转可能晚于点击回执。先读当前页面，不因瞬时仍在旧页重复提交。
- 支付跳到第三方认证不等于已支付。保存待付款订单号与到期信息；过期取消后先查全部/待付款，确认无有效新单才在原授权内重新创建。
- 物流退回而未收到：如实按实际收货状态申请，不虚构质量问题。已签收的无理由退货与仅退款区分。
- 官方退件可能受历史运费未支付限制；先记录阻塞，不静默代付其他订单欠款，也不把默认“2小时上门”误记成已预约。
- 系统会弹出其他可合退订单；只是建议，不等于用户授权退全部，核原目标和实物后选择。
- 已退款但包裹仍收到：单独准备联系商家说明，只有授权后发送；不能再申请第二次同额退款。

## 淘宝 / 天猫

- 核本人账号、店铺、订单和售后详情，收件人必须取自具体退货单，不从另平台同品牌推断。
- 商品标价/购物金后现金与经济支出分开。购物金、红包、券、预售款的可退与追回条件进入净成本。
- 单买结算后继续核店铺入会、平台会员、新客、消费券与跨店凑单。券门槛计算基数以页面为准，不能从商品吊牌价推断已达门槛。订单详情核红包/消费券分摊，收银台另核支付优惠；App和网页权益有差异时标缺口，不视网页价为全渠道最低。
- 确认收货或支付密码页不能自动代填；已有用户授权仍须遵守实际认证门禁。
- 同店不同售后可能有不同退货仓、标签或运费。预约对应具体售后，区间和费用必须回读；点击了预约按钮不能当成功。

## 海外站点

当前已验证的海外真实执行国家站点：无。下文是启用新站点时的检查方法，不是已支持平台的承诺。

按平台＋国家站点核验：语言、当地尺码/版本、货币、当地税、国际运费/关税、支付费和退款汇差，是否退回本国/海外仓、退货标签和投递/上门方式。多币种报价没有可核汇率就不合并排名。

首批可以选择Amazon某国家站、eBay某站或用户实际使用的品牌官网；仅标已观察到的能力，不因平台有卖家API就假设能读消费者订单/代办售后。没有经过本人账号实测的站点不宣称自动执行。政策有时效，执行前打开官方当前政策核对并留链接和日期。
